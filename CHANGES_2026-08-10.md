# CHAKRA-AI update

## Operational-output regression repair
- Restored visible deterministic stage `PASS`/`FAIL` results independently of any optional financial scenario.
- Restored the impact breakdown for failed spinning, weaving, wet-processing, material and fabric-waste rules using stage emissions and threshold exceedance, not invented rupee fines.
- The Action Plan now always combines the XGBoost first priority with the complete deterministic corrective-action sequence.
- Bulk Supplier Check and Supply Chain Risk Map now use the same operational failures instead of treating a zero financial scenario as automatic success.
- Replaced unsupported hardcoded regional averages with a comparison against a user-supplied sourced benchmark.

## Benchmark integrity correction
- Did not restore the old hardcoded 15.0 kgCO2e/kg “EU limit” or INR 6,300/tCO2e “export penalty”; those are not universal statutory textile rules.
- A sourced buyer scenario now returns an explicit `PASS` or `FAIL` plus monetary exposure when a price is supplied.
- Without a sourced buyer scenario, the app reports the XGBoost operational risk tier and does not invent a benchmark or financial penalty.
- Preserved the deterministic LCA, security controls, DPP/auditor workflow and interface structure.

## Workspace preserved
The four existing workspace areas are unchanged:
- Factory Carbon Calculator
- Bulk Supplier Check
- City-Wide Pollution Data
- Supply Chain Risk Map

## Interface cleanup
- Removed EXP-AI / XAI / repeated AI labels from user-facing controls.
- Renamed user-facing analysis labels to plain product terms such as Cost Breakdown, Supplier Review and Regional Insights.
- Removed redundant explanatory text that narrated obvious controls or charts.
- Replaced exaggerated or absolute recommendation wording with neutral, data-linked wording.
- Kept CHAKRA-AI as the product brand.

## Background security
- Argon2id password hashing and server-provisioned roles.
- HttpOnly, SameSite=Strict session cookie.
- CSRF protection for state-changing authenticated calls.
- Server-side RBAC and factory/tenant isolation.
- Separation of duties for DPP review/issuance.
- Login throttling and temporary lockout.
- API/request rate limiting and body-size limits.
- Explicit CORS origins and Trusted Host filtering.
- Origin validation for browser POST requests.
- Session idle timeout and user-agent binding.
- Security headers including CSP, HSTS in secure deployment, frame denial, MIME sniffing protection and privacy headers.
- Parameterized SQLite queries.
- Pydantic request validation.
- Browser-side sanitization for CSV-derived display values.
- Ed25519 signed DPP records and revocation support.
- Server audit logging.
